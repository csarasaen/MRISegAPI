⚠️ Model files — NOT in the repo

The trained weights are large binary files. You need to place them at:

models/
├── Unet_SR_UNet3D.json
└── Unet_SR_UNet3D_final.weights.h5

Generated by UNet3D_SR_training.py. Mount this folder at /models inside the container via -v or a Kubernetes volume.

✅ No model? Still works for tests

The test suite mocks super_resolve — all 5 tests pass without TensorFlow or model weights. Great for CI.

Getting started

Up and running in 3 steps

Choose your path — local Docker, tests only, or the monitoring stack.

Build the image from the repo root, mount your model weights, and the API is live at localhost:8000.

Step 1 — Build
# Run from the repo root (MRISegAPI/)
docker build -t mri-sr:latest ./app
Step 2 — Run (with model weights)
docker run -p 8000:8000 \
  -v "C:/path/to/your/models:/models" \
  mri-sr:latest
Step 3 — Test it's alive
curl http://localhost:8000/healthz
# → {"status":"ok"}

curl http://localhost:8000/ready
# → {"status":"ready"}  (only once model is loaded)
💡 Tip: Open http://localhost:8000/docs in your browser to get the interactive Swagger UI — you can upload a .raw file and try the API with zero code.
⚠️ GPU nodes: The default Docker image uses the CPU TF build. For GPU inference, change the base image tag in app/Dockerfile to tensorflow/tensorflow:2.16.1-gpu and ensure NVIDIA Container Toolkit is installed.

No GPU, no model weights needed — the tests mock the inference function.

Install and run
# From repo root
pip install -r app/requirements.txt pytest httpx

pytest app/tests/ -v

# Expected output:

API Reference

Endpoints

The service exposes 4 endpoints. You only need POST /super-resolve for inference.

GET
/healthz
Always returns {"status":"ok"}. Use for K8s liveness probe — responds immediately with no model check.
GET
/ready
Returns 200 only after the 3D U-Net is loaded. Returns 503 if model files are missing. Use for K8s readiness probe.
GET
/metrics
Prometheus metrics endpoint — request counts, latency histograms. Scraped automatically by Prometheus.
POST
/super-resolve
Upload a .raw LR volume as a multipart file. Returns the super-resolved HR volume as raw bytes. Main endpoint.

POST /super-resolve — parameters

NameTypeRequiredDescription
fileuploadrequiredThe .raw binary file — packed voxels, no headers
x, y, zintrequiredLR volume dimensions in voxels. Used to verify file size = x×y×z×sizeof(dtype)
lr_spacingfloatrequiredLR voxel size in µm — e.g. 5.38. Must be > hr_spacing
hr_spacingfloatrequiredTarget HR voxel size in µm — e.g. 0.65. Scale = lr/hr ≈ 8.28×
dtypestrfloat32Input voxel type: float32, uint16, int16, float64, uint8
lr_norm_lo / hifloatautoNormalisation bounds. If omitted, estimated from the scan's own 1st–99th percentile
out_dtypestrfloat32Output dtype: float32 (0–1) or uint16 (0–65535)
overlapint16Tile overlap in HR voxels. Higher = smoother seams, slower
batch_sizeint4Tiles per GPU batch. Reduce if OOM; increase if GPU has headroom

Call the API — curl & Python

curl
curl -X POST \
  "http://localhost:8000/super-resolve?\
x=200&y=200&z=100&\
lr_spacing=5.38&hr_spacing=0.65" \
  -F "file=@scan_float32_200x200x100.raw" \
  --output scan_SR.raw

# Output filename from Content-Disposition:
# scan_SR_float32_1656x1656x828.raw
Python
import httpx, numpy as np
from pathlib import Path

raw = Path("scan.raw").read_bytes()
resp = httpx.post(
  "http://localhost:8000/super-resolve",
  params={"x":200,"y":200,"z":100,
          "lr_spacing":5.38,
          "hr_spacing":0.65},
  files={"file":("scan.raw",raw)},
  timeout=600,
)
resp.raise_for_status()
Path("scan_SR.raw").write_bytes(resp.content)
💡 Swagger UI: Navigate to http://localhost:8000/docs for a fully interactive UI — upload your .raw file, fill in the form fields, and download the result directly in your browser.

Kubernetes deployment

How the service runs on EKS

One YAML file defines three Kubernetes resources that work together to run the service reliably at scale.

Deployment

replicas2 (min)
imageghcr.io/csarasaen/MRISegAPI

Memory limit2 Gi
livenessGET /healthz
readinessGET /ready
userappuser (non-root)
Service

mri-seg-svc

typeLoadBalancer
port80 → 8000
selectorapp: mri-seg

AWS provisions an ELB automatically when type=LoadBalancer. Your API URL comes from the ELB's DNS name.

HorizontalPodAutoscaler

mri-seg-hpa

min pods2
max pods20
scale up whenCPU > 70%
or whenMemory > 80%

Under a burst of scan jobs, K8s automatically launches new pods up to 20 replicas. When load drops, it scales back down to 2.

Deploy to EKS (after terraform apply)
# Apply the K8s manifests
kubectl apply -f kubernetes/manifests/deployment.yml

# Watch pods come up
kubectl get pods -w

# Get the public URL
kubectl get svc mri-seg-svc

Key decisions explained

Why was it built this way?

Click any question to see the reasoning.

🔒 Why are model weights NOT in the Docker image?
▾

Baking multi-GB weight files into the image creates massive images that are slow to pull and push. It also ties a specific model version to the image tag, making weight updates require a full rebuild and redeploy. Mounting via a Kubernetes volume (or -v locally) means you can swap weights without touching the image at all — and avoids accidentally leaking proprietary model data in a registry.

⚡ Why is TensorFlow loaded lazily?
▾

Importing TensorFlow at module level would make every test import fail unless TF is installed — adding ~2 GB to the CI environment. By importing inside _configure_tf() and get_model(), the tests run with only the lightweight deps (fastapi, numpy, etc.). The model is also cached globally after first load so subsequent requests pay no reload cost.

💰 Why Spot instances for GPU nodes?
▾

GPU instances (g4dn.xlarge) are expensive — ~$0.53/hr on-demand. Spot instances offer the same hardware at ~70% discount. Super-resolution jobs are retry-able (stateless REST calls), so an occasional Spot interruption just triggers a client retry. The HPA keeps 2 pods running; Spot suits the inference worker pool, not the always-on baseline.

👤 Why run as a non-root user in Docker?
▾

Medical data workloads are typically subject to compliance requirements (HIPAA, GDPR). Running as appuser (non-root) is a security baseline — if the container is compromised, the attacker has limited filesystem write access. Most production Kubernetes security policies (PSP / OPA) also block root containers by default.

📐 Why does the API validate file byte size?
▾

A .raw file has no header — the API can't detect corruption by inspecting it. Checking that len(bytes) == x × y × z × sizeof(dtype) catches the most common user errors: wrong dimensions, wrong dtype, truncated upload, or a non-.raw file submitted by mistake. This fails fast with a 400 before any expensive model inference runs.

🔄 What does the HPA actually do?
▾

The HorizontalPodAutoscaler watches CPU and memory usage across all running pods. When average CPU exceeds 70% or memory 80%, it launches new pods — up to 20. Each pod handles one super-resolution job (inference is single-threaded per pod). When load drops, it terminates extra pods back to the minimum of 2. This means the service automatically scales for burst scan batches without manual intervention.
